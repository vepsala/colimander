Colimander

Per-project dev VMs on macOS, with a host-side credential broker so the agent doesn't hold your real tokens.

The problem

I work on 3 projects in parallel on an M3 with 36 GB of RAM. That isn't enough to keep three fully-provisioned dev environments running, with language servers, Postgres, browsers and agent VMs all stacked.

Agents like Claude Code work best when they can use the whole environment: real language servers, real databases, real tools. The usual cost is that the agent also has your real GitHub token, your real database password and your real filesystem.

Colimander tries to help with two things:

  • Lifecycle: spin up, switch between and tear down environments without losing track of what's where.
  • Less at stake: run an agent with fewer permission prompts, with less to lose if something goes wrong.

How it works

Each project is a Colima profile with its own VM, disk and Docker context, and no host bind-mount. Real credentials stay on the host. The VM gets local-only handles, and a host daemon brokers the sensitive connections, using the real credential only for operations its policy allows.

One VM per project

Each profile is a Colima VM with its own disk and Docker context. Create them with colimander setup or the Mac app.

No host bind-mount

Project files live only inside the VM. You edit over SSH from your editor, and the VM can't read your Mac's files.

Credential broker

GitHub, Fly and Doppler calls go through a daemon on your Mac. The policy can be finer than a fine-grained PAT, for example allowing writes to two repos but denying repo deletion.

Database proxy

Agents connect to Postgres through local credentials you can rotate. It can mask columns, scan results for things like emails and card numbers, and hold writes for your approval.

Egress monitoring

See which domains each sandbox's web traffic goes to and how much data was sent. It records traffic, it doesn't block or decrypt it.

Mac app

One window for sandboxes, egress, broker activity, databases and tokens. Every broker request is logged.

Why a broker

Many agent sandboxes try to stop credential theft at the network layer, with egress allow-lists, DNS filtering and firewall rules. Colimander takes a different angle: if the credential in the VM doesn't work off your machine, a leaked credential matters much less.

That doesn't make the agent safe. It can still do anything the broker policy allows, anything inside the VM, and it can still leak your code or data. The broker only limits what the credentials themselves can be used for.

Try it

git clone https://github.com/vepsala/colimander.git
cd colimander
make app

This builds the CLI and the Mac app, starts the daemon and opens the app. You need macOS, the Xcode command line tools, Go, Colima and gh. The README has the details and the CLI usage.

Limits

Helps with

  • An agent reading or writing your Mac's files
  • Credentials that keep working after they leak
  • One project's credentials being used in another

Doesn't help with

  • Anything the broker policy allows
  • Leaking code or data from inside the VM
  • Root inside the VM getting around the VM-side rules
  • A kernel exploit that escapes the VM
  • You typing a real secret into the VM yourself
  • macOS itself being compromised

None of this is foolproof. It reduces accidental exposure and shows you what's happening, but it won't stop a determined attacker.
